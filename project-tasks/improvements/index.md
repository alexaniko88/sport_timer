# Improvements

This folder is only for improvement tasks: changes that make existing, working behavior easier to use, clearer, faster, or easier to maintain. Broken behavior belongs in [Bugs](../bugs/index.md). Broader new capabilities can use the epic/story structure.


## Proposing an improvement

Create one numbered Markdown file directly in this folder, such as `01-simplify-timer-settings.md`. Keep numbers stable and use the next unused number for new proposals. Use `IMP-01` as the task identifier so it is distinct from story and bug tasks.

Each task should describe current behavior, the proposed change, who benefits and why, scope/exclusions, dependencies, open decisions, observable acceptance criteria, and relevant validation. Mark unresolved proposals Provisional rather than treating them as agreed requirements.

An improvement task does not authorize implementation. Plan and agree the change through the applicable orchestration workflow before changing application code.
