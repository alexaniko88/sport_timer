# Bugs

This folder is only for bug tasks: reports of existing behavior that is broken or differs from the expected behavior. New features and improvements belong elsewhere.

## Reporting a bug

Create one numbered Markdown file directly in this folder, using a name that describes the bug. Keep numbers stable and use the next unused number for new reports. Use `BUG-01` as the task identifier so it is distinct from story and improvement tasks.

Each task should describe the problem, expected and actual behavior, reproduction steps when known, relevant device/app details, impact, dependencies, acceptance criteria, and verification. Separate confirmed facts from suspected causes; unknown reproduction details do not prevent recording a report.

A bug report does not authorize implementation. Diagnose and agree the fix through the applicable orchestration workflow before changing application code.
